## Workloads

- **P1 (primary)** — analytics data lake, Parquet on object storage, read-dominated
  scan-heavy queries, lossless only. Authoritative when choices conflict.
- **S1 (secondary)** — streaming logs/events, latency-sensitive hot path, lossless only.
  Used as a design check so P1 conclusions do not silently assume batch context.

## Layout

```txt
benchmarks/   env capture, memory profiler, benchmark cell, subprocess runner, orchestrator, cost model
security/     safe_decompress.py — bounded decoding for untrusted input
scripts/      dataset profiling, reader-compatibility probe, result analysis
tests/        correctness, edge cases, hostile inputs, fuzz fixtures
docs/         problem statement, methodology, threat model, catalog, compatibility, results, iteration log
data/metadata/ dataset fingerprints and column profiles (no bulk data)
data/raw/     source Parquet files — gitignored, you supply these (see below)
results/      raw per-cell JSON + run manifests + analysis output
```

### `results/`

| Path | What it is |
| --- | --- |
| `results/raw/<dataset>__<scale>__<arm>.json` | **Generated, committed, append-only.** One cell per file, integer bytes and millisecond durations. Never edited after the fact — they are the recorded evidence |
| `results/latest_manifest.json`, `manifest_<run_id>.json` | Which cells a given sweep produced. `analyze_results.py` reads **only** these, so stale cells from earlier sweeps can never leak into an analysis |
| `results/summary.json` | Generated per-comparison gate evaluations (G1–G8) |
| `results/{correctness,security}_results.json` | Generated by the test suites |

`docs/results.md` is the human-readable current-state table derived from the above;
`docs/iteration-log.md` is the append-only narrative, one entry per iteration.

## Reproducing

```bash
pip install pyarrow cramjam zstandard

# 1. Supply the datasets. URLs + SHA-256 are in data/metadata/catalog.json.
mkdir -p data/raw && sha256sum data/raw/*.parquet    # must match the catalog
# or point elsewhere: export COMPRESSION_BENCH_DATA_ROOT=/path/to/parquet

# 2. Run
python3 tests/test_hostile_inputs.py                        # security suite
python3 tests/test_correctness.py                           # correctness suite
python3 scripts/probe_reader_support.py --write /tmp/compat # compatibility probes
python3 benchmarks/orchestrate.py --catalog data/metadata/catalog.json --trials 10
python3 scripts/analyze_results.py
```

`pytest` also works, but it is a **wrapper**: it shells out to the two suites above and
asserts their exit codes. The suites report pass/fail via exit code and JSON, not via
`assert`, so collecting their `test_*` functions directly would report green on failure —
`tests/conftest.py` prevents that.

Set `COMPRESSION_BENCH_ENV=cloud-<shape>` when running on real hardware. It defaults to
`sandbox`, and results carry that label so they can never be misread as validated.

## Ground rules

Baseline before optimization. One meaningful variable per iteration. No improvement
claimed without reproducible benchmark evidence. External compressed input is hostile.
Ratio alone is never sufficient — memory, latency, correctness, compatibility and security
are hard constraints.
